# MIGRATION — карта переноса в Grok Bot

Модель Grok Bot: навыки (skill.md = имя + описание + когда применять), рутины (промт + расписание или событие-триггер), плагины-коннекторы, свой компьютер (Linux + shell + браузер), память, страницы-отчёты.

## Что не переносится / сломается первым (три вещи)

1. **Notion-карточки**: формат полей (рубли, URL, статус) продублируется только если Notion-коннектор Grok Bot умеет то же поле-свойство «Документы» (url) и загрузку в тело страницы; иначе карточки сведутся к текстовым страницам.
2. **zakupki.gov.ru скачивание** с российской машины (CA + RU IP) — на Linuxиках вне RU процесс падает первой же попыткой; со всех зарубежных адресов просто нельзя.
3. **Composio-Drive texting**: GO-Drive «UPLOAD_FILE» принимает только s3key-этапы, а «CREATE_FILE_FROM_TEXT» — текст ≤10 MB; бинарные оригиналы ТЗ не улетит автоматом — только руками.

## Пробелы (чего в пакете нет / сам не смог закрыть)

1. «Russian Trusted Root CA» дистрибутив/получении не описан (не знаю, где сейчас есть).
2. Точные названия методов Drive-коннектора Grok Bot не известны (описаны воздействия; сверить при установке).
3. Текущая схема полей Notion получена через MCP-схему; может отличаться YAML-номенклатура полей в Grok-модели (переписать названия полей при миграции).
4. Ценовые источники вне аптек (мед-ях. medams/lab-medica) не испытаны; добавляйте источники по необходимости.
5. `fixtures/` swagger-набор ответа gosplan API (не перенесён в пакет; наход༉ted из локальной машины).
6. Локальные логи run_*.json/долив — не переносить (мусор прогона).
