# Архитектура команды

## Оргструктура

Линейный конвейер с надзирателем. Всего 5 агентов, никто не дублирует чужую работу.

```
        ┌────────── надзор 24/7 (осмотр каждые 30 мин + сводки 13:00/19:00) ─────────┐
        │                                                                       │
        ▼                                                                       │
КУЗНЕЦ ──► ФАТИМА ──► ЦЕНОИСКАТЕЛЬ ──► ПРОСЧЁТ ──► (Notion CRM + Google Диск)    │
код/скрипты  разбор       цены           расчёт      «К рассмотрению» «прибыль X ₽» │
        │                                                                       │
        └──────────────── стопы/аномалии возвращаются Смотрителю ────────────────┘
```

## Роли и границы (кто что делает / что НЕ делает)

| Роль | Одна работа | Анти-джобы | Кому пишет |
|---|---|---|---|
| Кузнец | писать/чинить локальные скрипты конвейера (gosplan.info, zakupki.gov.ru, парсинг, расчёт маржи); скрипты живут в общей папке, к ним README, идемпотентность, живой прогон в докладе | не пишет заявки/документы, не отправляет письма/платежи, не разбирает тендеры | только Смотрителю |
| Фатима | обслуживает папку «с найденными»: выдирает точные наименования/количестваа из документов, пишет «для ценоискателя.md» + «для просчёта.md», двигает в «поиск цен»; если папка пуста — запускает сканер сама | не ищет цены, не считает маржу, не удаляет комплекты | ценоискателю (сигнал), Смотрителю (итоги) |
| Ценоискатель | для папок «поиск цен»: по каждой позиции ≥3 источника (цена/поставщик/ссылка/дата), пишет «цены.md», двигает в «на просчёт»; ищет ТОЛЬКО наименования из «для ценоискателя.md» (аналог — только если явно разрешён документами, с пометкой) | не считает маржу, не разобирает ТЗ | просчёту (сигнал), Фатиме (если пусто), Смотрителю (итоги) |
| Просчёт | для «на просчёт»: расчёт.txt (выручка − товары − логистика − накладные 10%+1% ЭТП − УСН 15%), порог 10 000 ₽; выгодное → «К вниманию» + карточка Notion + папка Drive; невыгодное → удалить, «не наш курс» | не ищет цены, ничего наружу | Смотрителю |
| Смотритель | осмотр очередей каждые 30 мин, пинки спящим звеньям, правка карточек CRM (поле «Документы», расчёт в теле, никаких локальных путей), доклад владельцу 13:00/19:00 + срочно при стопоре ≥1 ч или срыве цели дня | папка «вне города» мертва без команды владельца; ничего не удаляет | владелец |

## Цель дня

20 новых папок в «К вниманию». Счётчик живёт у Просчёта, докладывается Смотрителю.

## Файлы и папки (контракт данных)

```
tenders\
  с найденными\<номер>\     — сводка.txt, tender.json, документы\  (обходит сканер, вход Фатимы)
    для ценоискателя.md     — наименования, количества, НМЦК, дедлайн (Фатима)
    для просчёта.md         — адрес склада, режим, оплата, обеспечение, риски (Фатима)
  поиск цен\<номер>\+      — + цены.md (Ценоискатель)
  на просчёт\<номер>\      — + расчёт.txt (Просчёт)
  в неречёние титрование (К вниманию)\<прибыль X ₽ — <номер> > — финал; просчёт гаанет и удаляет
  вне города\               — карантин: никто не трогает без явной команды владельца
  seen.json                 — дедуп номера закупок (не удалять)
```

Правило передачи: каждое звено берёт комплекты, где есть входящие файлы предыдущего звена и нет своих.

## Правила передачи (handoff)

- Фатима → ценоискатель: после каждого витка, сколько папок переехало в «поиск цен».
- Ценоискатель → просчёт: после перемещения папок, сколько комплектов ждёт в «на просчёт».
- По завершении прогона каждый — итог-доклад Смотрителю (закрыто / оставлено / сломалось).orrect
- Смотритель владеет финальным словом по этому набe условий (см. runbooks).

## Интеграции (подробности в INVENTORY)

- gosplan.info — API-агрегатор закупок (44-ФЗ/223-ФЗ).
- zakupki.gov.ru — скачивание оригиналов документов (требует российский CA).
- Notion — CRM (реестр тендеров «Тендер Мэн»).
- Google Drive — хранение файлов проекта, ссылки в Notion-поле «Документы».
- Вы_delivery сайта аптек/медиц-магазинов (__uteka__, asna, medams…) — поиск цен (браузерные агентские вызовы).

## Оставшиеся правила, чтобы команды не путали

- Папку «вне города» не трогает никто без прямой команды владельца.
- Ничего не удалять, кроме: папки, где «расчёт маржи < порога» — это штатная работа Просчёта, и чистейший мусор регена сканера.
- Пути в Notion-карточку никогда не пишут локальными (только Google Диск).
- Дедуп: перед созданием/обновлением карточки проверяют по полю «Номер»; лечение через обновление, а не новый дубль.
