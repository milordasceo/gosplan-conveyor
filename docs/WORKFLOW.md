# WORKFLOW — путь одного тендера от публикации до решения

Путь: **публикация → скан → разбор → поиск цен → расчёт → CRM/Диск → решение владельца**.

## Шаг 0. Настройки (один раз)

Конфиг сканера `scripts/config.novosibirsk.yaml`:
- источник gosplan.info v-API, источники `fz44` + `fz223`;
- бюджет 30 000–150 000 ₽, `stage: 1` (только приём заявок), `regions: [54]`;
- клиентская проверка города `delivery_cities: ["Новосибирск"]` (сервер не фильтрует по городу);
- дедуп `seen.json` — не удалять.

## Шаг 1. Сканер (скрипт, не агент)

`python gosplan_scanner.py -c config.novosibirsk.yaml --collect 20`

- Находит до 20 свежих закупок по фильтрам, **если** папка «с найденными» пуста (иначе ничего не делает).
- Для каждой: папка `tenders\с найденными\<номер>\` с `сводка.txt` (объект, НМЦК, сроки, заказчик, ссылка), `tender.json` (ответ API), `документы\` (скачанные с zakupki.gov.ru файлы: проект контракта, описание, ТЗ).
- Ничего не удаляет; повторный прогон переносит 0.

## Шаг 2. Фатима (разбор, ≤5 за виток)

Для каждого комплекта, где ещё нет её файлов:
1. Читает `сводка.txt`, `tender.json`, тексты из `документы\`; для старых .doc/.rtf/.pdf сначала запускается `python scripts/extract_subject.py <папка>` (даёт тексты .txt и `предмет.md`).
2. Пишет внутри папки:
   - `для ценоискателя.md` — **конкретное наименование строго из ТЗ** (название, характеристики, объём, мера, количества), НМЦК, дедлайн; без пересказа/обобщений.
   - `для просчёта.md` — условия поставки: адрес склада, режим, порядок оплаты, обеспечение, риски.
3. Проверяет адрес поставки: вне Новосибирска → не берёт в разбор (остаётся, карантин «вне города» принимает `python check_cities.py`).
4. Перемещает папку в `tenders\поиск цен\`.

## Шаг 3. Ценоискатель (≤3 за виток)

Для каждой папки «поиск цен», где есть `для ценоискателя.md` и нет `цены.md`:
1. Ищет по наименованиям из файла (браузерный поиск, geo-ограничение Новосибирск/НСО) минимум 3 разных источника: цена за единицу, поставщик, ссылка, дата проверки. Ищет **только** то, что дано; аналог — только если в документах явно разрешено, и тогда пометка «аналог по ТЗ (разрешено документами)» или «точно как в ТЗ».
2. Пишет `цены.md` (таблица источников + лучший расклад + оговорки: розница/опт, термолабильность, ЖНВЛП).
3. Перемещает папку в `tenders\на просчёт\`.

## Шаг 4. Просчёт (≤5 за виток), порог маржи ≥ 10 000 ₽

Для каждой папки «на просчёт» с `цены.md`:
1. Считает: выручка (НМЦК) − товары (лучший расклад из `цены.md`) − логистика (Новосибирск: потолок 3 000 ₽ или факт дешевле) − накладные (10% себестоимости + 1% ЭТП РТС) − УСН 15%. Пишет `расчёт.txt` (вход, позиции, расчёт по шагам, вердикт, риски).
2. **Маржа ≥ 10 000 ₽** → победители:
   - переименовать папку `прибыль X ₽ — <номер>` и переместить в `К вниманию\`;
   - Notion: карточка в реестре тендеров по шаблону «Журнал и правила» (поле-эталон: Рокурония). Поля: Название «товар / X ₽», Номер, Ссылка (zakupki), Закон, Способ, Заказчик, Площадка, Подача/Поставка до, Куда везти, Расходы/Прибыль/Налог/Себестоимость ₽, Где купить, Дата находки, Вердикт «БРАТЬ/ПОД ВОПРОСОМ», Комментарий, Статус «К рассмотрению».
   - Google Drive (Composio): создать `Тендеры/<номер>`, залить текстовые файлы комплекта (сводка.txt, цены.md, расчёт.txt; бинарники не заливаются — zakupki недоступен из Composio).
   - В карточке: поле «Документы» = ссылка Drive-папки; в теле — маркерный список файлов со ссылками; никаких локальных путей.
   - Дедуп по полю «Номер»: есть — обновить; карточку после создания проверить (пустая «New page» — ошибка, переделать).
3. **Маржа < 10 000 ₽** → удалить папку, вердикт «не наш курс».
4. По адресу вне города — не считать/не двигать, пометка «вне города»; решение за владельцем.

## Шаг 5. Смотритель (контроль)

- каждые 30 мин: очереди, стагнация (>1 час), пинки спящим; выборочная правка карточек.
- 13:00/19:00: сводка владельцу — N/20, узкие места, что починил/сломалось.
- срочно: если конвейер стоит ≥1 час или цель дня срывается.

## Шаг 6. Человек

Решение «брать/не брать» по каждой карточке «К рассмотрению» принимает человек. До подачи заявки просмотр ЖНВЛП и сверка единиц предельной НР-цены (20-пинк из расчётов: «сверить единицы НР вручную до подачи») — тоже человек.
